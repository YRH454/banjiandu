# 代码版本与复现注意事项

## 实际训练定义

- 输入图像 384×384；文本上限 256 token。ViT 第 10–11 块 Q/V 使用 LoRA rank 4、alpha 8；跨模态 cross-attention 第 6–11 层 Q/V 使用 LoRA rank 8、alpha 16。
- 每步 16 个不同的 L 正锚图；每图一正一负，形成 32 个图文对。BCE 是单 logit 图文匹配损失。Pair-USA 的 16×16 关系只取 L 正对，不直接使用 U。
- G3/G4 每个有效 OT 步还抽取 32 个 U 图文对，基于学生融合 CLS 形成 32×32 软目标。OT `epsilon=0.1`、最多 100 次、双边边缘残差 `≤1e-5`，不收敛时不得跳过该步。
- AdamW：LoRA LR `1e-4`，任务头 LR `2e-4`，weight decay `0.01`；80 步预热后余弦日程，梯度范数上限 1。Pair-USA 和 OT 的辅助权重在前 100 步为 0，并于 101–200 步升至 0.1。
- FP16 初始 loss scale 1024，溢出时同一步退避重试。每 50 步保存 last、每 100 步验证；优先按 paired accuracy、其次 AUROC 选择最佳权重。

## 版本与限制

G2/G3/G4 都从对应 G1 的 **best 权重**重新开启 1600 步阶段，采用新的优化器与学习率日程，而不是恢复 G1 的优化器状态。历史 G3/G4 的 5%/20% 四组使用 `archive/pre_recovery_solver/` 中的初版 OT 求解器；其余六组用当前 `code/ot_loss.py` 的等价数值加速实现。不要混淆二者来源。

历史源文件保留本机 `G:`/`C:` 等路径，历史运行指纹与这些文件逐字节绑定。该仓库仅保存代码、登记与计划，不保存执行时生成的逐组配置和审计/结果 JSON，因为它们包含数据及绝对制品路径。可移植运行器和干净环境验证尚未完成；不要仅凭本仓库声称可以精确重跑历史指标。

新种子入口见 `experiments/apple_itm_g1_g4_multiseed_v1/README.md`。`20260826`、`20260827` 尚未执行。该入口省去历史独立 B 学生，仅训练 G1–G4 和按预算的 USA 教师；预算间随机流消耗与历史完整 A/B 队列不同。G1/G2 的历史训练器断点不保存完整 RNG；中断恢复不能保证与不中断运行逐位一致。G3/G4 的断点包含 RNG 状态。

## 环境记录

历史机器为 Windows、Quadro RTX 5000、Python 3.9.4、PyTorch 2.5.1+cu121、torchvision 0.20.1+cu121、timm 1.0.24、transformers 4.57.6、NumPy 1.26.4、scikit-learn 1.0.2、Pillow 11.3.0。此处只是实际环境快照，不是经干净安装验证的依赖锁。不同 CUDA/驱动或依赖版本可能导致数值和性能差异。
